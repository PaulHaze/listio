# Work tracking: sprint files (no GitHub Issues)

This repo does **not** use GitHub Issues. Work is planned and tracked as numbered sprint
files in [`docs/sprints/`](../sprints/README.md), e.g. `01_Scaffolding_Astro_Vitest_Cloudflare.md`.

## Conventions

- Sprints are worked **one at a time, in number order**.
- Each sprint file has a **Status** line (`not started` / `in progress` / `done`), a task
  checklist, and a **Done when** section. Tick tasks as they're completed and keep the
  status table in `docs/sprints/README.md` in sync.
- New work goes into the relevant sprint's task list, or a new numbered sprint file.

## When a skill says "publish to the issue tracker"

Add the work to the relevant sprint file (or create a new numbered sprint) instead.

## When a skill says "fetch the relevant ticket"

Read the relevant sprint file in `docs/sprints/`.
